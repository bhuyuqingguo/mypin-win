# 需求说明（Requirements）

本文档记录 MicPin for Windows 的需求来源、功能拆解与验收标准。
需求按提出顺序分为四个批次：**R1 移植基线 → R2 主界面 → R3 排序与屏蔽 → R4 高分屏与视觉**。

---

## 1. 背景

macOS 上存在的痛点，在 Windows 上同样存在且更明显：Windows 会把“最近插入的设备”或蓝牙耳机
（Hands-Free / 通话端点）设为默认录音设备，导致

- 插入 USB 麦克风后，会议/听写类软件仍然用内置麦克风阵列；
- 用 AirPods 听音乐时输入被切到耳机麦克风，音质与音量都变差；
- USB 麦克风拔掉后系统掉回内置麦，重新插上又需要手动改回来；
- 有多个 USB 麦克风时无法表达“优先用哪一个”。

目标是做一个**零配置、低占用、不打扰**的常驻小工具：插上 USB 麦克风就赢，其他情况不乱动系统设置。

## 2. 目标与非目标

**目标**

1. 让所有“跟随系统默认输入”的应用（听写、Typeless、Zoom、Meet、Slack huddle 等）总能拿到正确的麦克风。
2. 插上 USB 麦克风即成为默认输入，无需手动设置。
3. 不被蓝牙耳机抢走输入。
4. 用户可显式锁定某个设备；该设备离线时保持系统默认不动。
5. 多麦克风场景可控：可排序、可临时屏蔽。
6. 常驻运行成本极低（内存数 MB、无网络、无额外权限）。
7. 提供可操作的主界面，而不只是托盘菜单。
8. 高分屏（150% / 200% 缩放）下清晰锐利，界面美观易用。

**非目标（明确不做）**

- 不修改应用内部单独指定的输入设备。
- 不做音频路由/混音/降噪/录音功能。
- 不联网、不收集遥测、不做账号体系。
- 不要求管理员权限，不安装驱动。

## 3. 角色与场景

| 角色 | 场景 | 期望结果 |
| --- | --- | --- |
| 桌面办公用户 | 插入 USB 麦克风开线上会议 | 系统默认输入立即变为 USB 麦克风，会议软件无需设置 |
| 音乐/通勤用户 | 戴蓝牙耳机听歌时开会 | 输入仍为 USB 麦克风，不切到耳机通话麦 |
| 多设备用户 | 桌面麦 + 领夹麦同时在位 | 按自己排的顺序选第一个在线的 |
| 临时切换用户 | 想暂时停用某个麦克风做对比 | 一键屏蔽，退出程序后自动恢复 |
| 只用内置麦的用户 | 没有 USB 麦克风 | 程序待机，**不修改**系统默认 |
| 高分屏用户 | 2880×1800 200% 缩放 | 文字与控件按原生像素绘制，不发虚 |

## 4. 功能需求

编号规则：`FR-x` 为功能需求，`NFR-x` 为非功能需求。优先级：P0 必须、P1 应该、P2 可选。

### FR-1 设备发现与分类（P0）

- 枚举所有**活动的采集端点**（`eCapture` + `DEVICE_STATE_ACTIVE`）。
- 为每个端点读取 `FriendlyName`（缺失时回退 `DeviceDesc`）与 `EnumeratorName`。
- 归类为五类：`USB`、`Built-in`、`Bluetooth`、`Virtual`、`Other`。
- 分类规则必须能识别本机真实环境：内置麦克风的枚举器可能是 `SOUNDWIRE`（骁龙平台的
  Cirrus Logic XU），不能只识别 `HDAUDIO`。

**验收**：`MicPinDiag.exe` 输出中，内置麦克风阵列显示为 Built-in，VB-Audio CABLE 显示为 Virtual。

### FR-2 自动模式选择（P0）

- 按用户设定的优先级顺序遍历设备，选出**第一个 USB 类且未被屏蔽**的设备。
- 内置、蓝牙、虚拟、未知类永远不参与自动选择。
- 没有可用 USB 麦克风时，返回“无目标”，**不修改系统默认设备**。

**验收**：只有内置麦时，系统默认输入保持不变；插入 USB 麦后 1 秒内切换过去。

### FR-3 锁定模式（P0）

- 用户可锁定任意一个具体设备（不只是 USB 类）。
- 锁定设备在线 → 强制为系统默认；离线 → 保持系统默认不动，并在界面/菜单提示“未连接”。
- 再次选择同一设备或选择“自动”即解除锁定。
- 锁定关系持久化。

**验收**：锁定设备拔掉后系统默认不再被程序改动；重新插上后自动恢复锁定。

### FR-4 强制生效（P0）

- 通过未公开的 `IPolicyConfig::SetDefaultEndpoint` 设置默认设备。
- 必须同时设置 `eConsole`、`eMultimedia`、`eCommunications` 三个角色。

**验收**：设置后 `GetDefaultInputId` 对三个角色均返回目标设备 id。

### FR-5 变更监听与看护（P0）

- 订阅设备插拔、设备状态变化、默认设备变化事件。
- 事件到达后去抖 350ms 再评估，避免瞬时抖动导致反复切换。
- 兜底轮询 3 秒一次，防止漏事件。

**验收**：外部把默认设备改成内置麦后，3 秒内被改回目标设备。

### FR-6 防抢设备（P0）

- 15 秒内发生超过 6 次切换，判定为与其他音频程序互相抢夺。
- 进入 20 秒退避期，期间不再强制切换，避免 CPU 空转与设备反复切换的爆音。

**验收**：模拟高频切换时不出现“无限对拉”。

### FR-7 托盘与状态（P0）

- 常驻托盘图标，三态：实心麦克风=已锁定，空心=已启用但无 USB 麦克风，打叉=已暂停。
- 左键单击/双击打开主界面；右键打开菜单。
- 菜单内容：打开窗口、当前输入、状态行、设备列表（自动 + 各设备，带类型标签）、
  四个开关（启用自动锁定 / 切换时显示提示 / 在任务栏角落显示设备名称 / 登录时启动）、
  立即重新检测、退出。
- 托盘 tooltip 显示当前设备名。

### FR-8 切换提示（P1）

- 每次实际发生切换时，在屏幕右上角显示淡入淡出 HUD（图标 + 「麦克风」+ 设备名），
  约 1.7 秒后淡出。
- 可在设置中关闭。
- “立即重新检测”也会弹一次 HUD（反馈式确认）。

### FR-9 设备名显示（P1）

- Windows 托盘图标旁无法常驻文字，因此“在菜单栏显示设备名”实现为
  **任务栏上方右侧的小浮标**（点击穿透，不获取焦点），并同步到托盘 tooltip。

### FR-10 开机启动（P1）

- 勾选后写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名 `MicPin`。
- 未勾选时确保该值不存在。

### FR-11 主界面窗口（P0，第二批需求）

- 除托盘菜单外必须有一个可操作的主界面窗口。
- 内容：当前输入（设备名 + 状态行 + 状态色点）、麦克风优先级列表、四个开关、按钮。
- 关闭窗口时隐藏到托盘，不退出程序。
- 窗口尺寸随设备数量自适应，避免大片空白。

### FR-12 优先级排序（P0，第三批需求）

- 列表中每个设备行可用 ▲▼ 调整顺序；首行不可上移，末行不可下移。
- 顺序立即影响自动模式的选择结果。
- 顺序持久化到设置文件。
- 掉线设备在顺序中的位置被保留：重排时先写当前在线顺序，再把未知 id 追加在后面。

**验收**：把 B 移到 A 之前，自动模式立刻改选 B；重启程序顺序不变。

### FR-13 临时屏蔽（P0，第三批需求）

- 任意设备（含非 USB）可被屏蔽；屏蔽后自动模式跳过该设备。
- 屏蔽是**会话级**的：不写入设置文件，程序退出即全部恢复。
- 屏蔽当前被锁定的设备时，自动解除锁定。
- 提供「全部恢复」一键清空所有屏蔽。
- 界面上被屏蔽行名称变灰，胶囊显示“已屏蔽”。

**验收**：屏蔽后重启程序，屏蔽状态不存在。

### FR-14 高分屏适配（P0，第四批需求）

- 进程声明 **PerMonitorV2** DPI 感知，不能依赖系统位图拉伸。
- 所有自绘尺寸、间距、描边按窗口所在显示器的真实 DPI 缩放。
- 窗口跨不同 DPI 显示器时重新布局。
- 1px 描边需像素对齐（向内对齐 / 半像素偏移），避免发虚。

**验收**：200% 缩放截图与 100% 结构一致，文字为 ClearType 原生渲染。

### FR-15 深色界面（P0，第四批需求）

- 主界面为深色主题，包含标题栏（DWM 沉浸式深色）。
- 系统默认的浅色复选框/按钮不能直接使用，需自绘以匹配深色底。
- 列表需有选中态、悬停态、分隔线、类型标签、状态胶囊。

**验收**：界面上不存在白底控件；禁用态仍可辨识。

### FR-16 本地化（P1）

- 中文（简体）与英文，跟随 `CultureInfo.CurrentUICulture` 是否为 `zh*`。
- 覆盖所有菜单项、状态行、标签、按钮与提示。

### FR-17 单实例（P1）

- 重复启动不产生第二个托盘图标，直接退出。

## 5. 非功能需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| NFR-1 | 零依赖 | 仅依赖 .NET Framework 4.8 与 Windows 自带组件，产物为单个 exe |
| NFR-2 | 免安装 | 绿色版，拷贝即可运行；配置写在 `%APPDATA%\MicPin\settings.json` |
| NFR-3 | 低占用 | 空闲内存数 MB；无定时器风暴（3 秒轮询 + 事件去抖） |
| NFR-4 | 不打扰 | 不在任务栏常驻窗口；关闭窗口即隐藏；不弹模态框 |
| NFR-5 | 健壮 | 音频子系统不可用、设置文件损坏、注册表写入失败都必须静默降级，不崩溃 |
| NFR-6 | 无权限要求 | 不需要管理员、麦克风权限、辅助功能、网络 |
| NFR-7 | 可诊断 | 附带控制台工具，能打印端点、默认值、选择结果与写入链路自检 |
| NFR-8 | 可维护 | 单一职责分层：COM 互操作 / 设备语义 / 应用逻辑 / 视图；C# 5 语法约束 |

### 相对 macOS 版的差异（有意为之）

1. **自动模式的判定依据**：macOS 版按名称关键词排序再退化为“任意 USB 输入”；
   Windows 版改为**用户显式排序**，去掉了关键词匹配（`PreferredKeywords` 已删除），
   逻辑更可预测，也解决了“关键词猜错”的问题。
2. **“在菜单栏显示设备名”**：Windows 无对应概念，改为任务栏角落浮标 + tooltip。
3. **新增**：优先级排序、临时屏蔽、深色主题、主界面窗口。

## 7. 验收清单（手工）

- [ ] 无 USB 麦克风时启动：状态为“未检测到 USB 麦克风”，系统默认输入未被修改。
- [ ] 插入 USB 麦克风：1 秒内成为默认输入，HUD 弹出并显示设备名。
- [ ] 在系统设置里把默认输入改成内置麦：3 秒内被改回。
- [ ] 锁定某设备后拔掉它：系统默认保持不变，界面显示“未连接”。
- [ ] 排序：把第二个设备上移一位，自动模式立即改选它；重启后顺序不变。
- [ ] 屏蔽第一个设备：自动模式选下一个；重启程序后屏蔽消失。
- [ ] 关闭自动锁定：程序不再改动默认设备，图标变为打叉。
- [ ] 关闭窗口：程序仍在托盘运行，左键可再次打开。
- [ ] 200% 缩放：文字清晰、无控件裁切、窗口高度随设备数变化。
- [ ] 重复双击 exe：不出现第二个托盘图标。
